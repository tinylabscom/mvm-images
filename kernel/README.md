# Slim microVM kernel

The slim Linux kernels owned and published by `mvm-images`. They are built
via `pkgs.linuxManualConfig` from a `.config` generated by `make defconfig`,
the local enable/disable lists, and `make olddefconfig`. Three kernels
derive from one shared base:

- [`base.nix`](./base.nix) — the minimal feature set every mvm guest
  boots (virtio, vsock, ext4/overlay, seccomp, …), `CONFIG_MODULES=n`.
- [`builder.nix`](./builder.nix) — base + builder-only infra
  (virtio-fs and namespaces/cgroups, with no guest NIC or firewall path).
- [`workload.nix`](./workload.nix) — base + dm-verity (verified boot), with
  compiler size optimization and workload-only namespace/cgroup removal.
- [`rootless.nix`](./rootless.nix) — the verified workload kernel plus the
  user/mount/PID/IPC/UTS namespace, cgroup v2, PTY and notification floor for
  generic rootless containers. It deliberately has no network namespace or
  network device; external traffic still uses FlowMux over vsock.

The locally owned image recipes import these definitions directly.
[`flake.nix`](./flake.nix) also exposes per-architecture `vmlinux`,
per-variant `configfile` and `metrics`, `resolved-configs`, and an
`artifact-manifest` containing the kernel version and config/artifact hashes.
The image-set workflows build, reproduce, sign, and publish these outputs.
`mvm` selects published kernels through its digest-pinned image lock; no
kernel build here reads `mvm` source.

The source of truth is the enable/disable lists in `base.nix` and the three
variant deltas. The built-in symbol budgets are owned here in
[`budgets.json`](./budgets.json).

## Why a slim, all-built-in kernel

Stock `pkgs.linuxPackages.kernel` ships hundreds of `=m` modules
the builder VM never loads, and required facilities can be modules too
(overlay, vsock, and virtio-fs). Under that shape, a guest init has to:

1. Ship the matching kernel module tree in the rootfs.
2. Modprobe each module at the right time (overlay before mount,
   vsock before `socket()`, fuse + virtiofs before mount).
3. Hope modprobe finds the module (silent failure modes on a
   missing closure entry).

That contract has multiple silent-failure surfaces. Slim compiles every
required feature as `=y` (built-in), with modules disabled. There is no
module tree to ship or load. No guest has a NIC; external networking uses
the authenticated FlowMux session over vsock, not a guest firewall path.

## Tradeoff: image-build kernel compilation

Because the config is novel, `cache.nixos.org` doesn't have a
substitute. A contributor's first image build may compile the kernel.
Builds and evaluations run on Linux or through a configured Linux builder.
Subsequent builds reuse matching Nix store outputs. Installing or running
`mvmctl` consumes published artifacts; it does not compile these kernels.

## Changing what's compiled in

Add a feature: drop its short Kconfig symbol (without the
`CONFIG_` prefix) into the `enables` list. `make olddefconfig`
will pull in transitive dependencies on the next build.

Remove a feature: add best-effort experiments to `baseDisables` or a variant's
`extraDisables`. Once the resolved config proves the cut, move it to
`requiredDisables` (or a variant's `requiredExtraDisables`). Config generation
then fails if `olddefconfig` silently selects the feature back on. A reverted
cut usually means that its selecting parent must also be removed; disabling a
leaf does not override a Kconfig `select`.

To introspect what `olddefconfig` produced, run the following from this
directory on a Linux builder and build the variant-specific config outputs
or the paired `resolved-configs` output:

```sh
nix build .#builder-configfile -o /tmp/builder.config
nix build .#workload-configfile -o /tmp/workload.config
nix build .#rootless-configfile -o /tmp/rootless.config
diff -u /tmp/builder.config /tmp/workload.config || true

nix build .#resolved-configs -o /tmp/kernel-configs
grep '=y$' /tmp/kernel-configs/workload.config | sort > /tmp/workload.y.txt
grep '=y$' /tmp/kernel-configs/builder.config | sort > /tmp/builder.y.txt
grep '=y$' /tmp/kernel-configs/rootless.config | sort > /tmp/rootless.y.txt
```

Per-variant metrics are first-class too:

```sh
nix build .#builder-metrics -o /tmp/builder-metrics
nix build .#workload-metrics -o /tmp/workload-metrics
nix build .#rootless-metrics -o /tmp/rootless-metrics
cat /tmp/workload-metrics/metrics.json
```

The default workload output is size-optimized. `workload-sizeopt-*` remains an
identical compatibility/measurement alias so existing release automation does
not need a flag migration.

The output is a regular `.config` text file — diffable across
`disables` edits to confirm SoC platform clusters or other
unwanted symbols are gone.

## Why no TSI patches

Builder and workload networking uses vsock. The TSI syscall-hijack
path is not part of these kernels; no TSI patches are required.

## Maintenance contract

When the kernel needs a change:

1. **Add a built-in feature.** Append the short Kconfig symbol to
   `enables`. `make olddefconfig` handles transitive deps.
2. **Remove a feature.** Append to `disables`. If `olddefconfig`
   pulls it back in, the parent also needs to come off.
3. **Bump the kernel version.** Edit `kernelVersion` in `base.nix` and
   the matching tarball `hash` (its own sha256 — `nix store
   prefetch-file mirror://kernel/linux/kernel/v6.x/linux-<ver>.tar.xz`),
   without reading or changing an `mvm` source pin. The pin is
   deliberately decoupled from nixpkgs'
   `linux_6_12` (which lags kernel.org's LTS point releases where CVE
   backports land). `make olddefconfig` reconciles dropped / renamed /
   added symbols automatically.

The default workload built-in symbol ceilings live in
[`budgets.json`](./budgets.json), separately for both architectures.
[`build-kernel-artifacts.sh`](../scripts/build-kernel-artifacts.sh) enforces
them through [`check_linux_layer.py`](../scripts/check_linux_layer.py), which
also checks architecture-specific kernel formats. The rootless kernel has its
own capability floor; do not apply the smaller default workload ceiling to it
or widen the default workload kernel for a rootless consumer.
